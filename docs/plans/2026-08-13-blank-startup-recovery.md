# Blank Startup and Recovery Diagnostics Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make normal launches open an empty workspace while preserving explicit-file and manual source recovery, and improve failure-stage diagnostics.

**Architecture:** The Svelte startup coordinator only opens an explicit launch source. The Rust session query becomes memory-only, while manual `open_source` keeps sidecar/cache migration behavior and emits a terminal success or failure event for each external stage.

**Tech Stack:** Svelte, TypeScript, Vitest, Rust, Tauri 2, cargo-xwin, GitHub Actions.

---

### Release correction discovered during asset verification

The first `v0.1.2` run exposed a hard-coded `0.1.1` filename in `scripts/package-macos.sh`: the application was built from 0.1.2 source, but its DMG, ZIP and checksum attachment names were stale. The packaging script must derive filenames from `src-tauri/tauri.conf.json`; then the invalid prerelease and tag must be replaced and the complete native workflow rerun before delivery.
