# 源视频同目录项目文件设计

## 目标与边界

用户选择一个受支持的 MP4 后，SpyCut 在源视频同一目录维护一个可见的版本化 JSON 项目文件。文件名为 `<源视频完整文件名>.spycut.json`，例如 `课程 01.mp4.spycut.json`。完整保留 `.mp4` 后缀可以避免文件名含点、同名素材或未来扩展输入格式时产生歧义。JSON 继续使用现有 `ProjectV1`，保存源文件身份、媒体信息、规范化删除区间、下一个区间 ID、播放位置、连接点复核状态和创建/更新时间；撤销/重做历史仍只属于当前会话。

源视频本身始终只读。项目文件路径只能由已经规范化的源视频路径推导，前端不能传入任意项目路径。此次不改变项目 schema、不增加手工导入/导出项目命令，也不扩大支持的视频格式。

## 真相源、兼容与恢复

同目录 sidecar 是项目内容的持久化真相源，应用数据目录中的 `projects/<project-id>.json` 降级为“最近项目启动缓存”。选择视频时先完成 ffprobe 和首尾指纹，再按以下优先级恢复：

1. 如果同目录 sidecar 存在，解析并校验 schema，再核对文件大小和首尾指纹；校验成功才恢复。
2. 如果 sidecar 不存在，扫描旧版应用数据项目并按现有指纹规则寻找匹配项。
3. 如果找到旧版项目，打开流程在刷新源身份和媒体信息后正常保存，从而自动生成 sidecar。
4. 如果两处都没有匹配项，创建新的 `ProjectV1`。

sidecar 一旦存在就具有优先权。损坏、schema 过新或指纹不匹配时，打开失败并保留原文件；不能静默退回旧缓存，也不能用空项目覆盖可能仍有价值的数据。应用启动恢复最近项目时，先从缓存取得最近源路径，重新检查源文件和指纹，然后再次读取 sidecar，避免缓存中的旧区间覆盖更新后的 sidecar。

## 保存、故障与原子性

每次已接受的编辑都在 Rust 工作流锁和会话写锁内保存。保存时在视频目录创建临时文件，写入 UTF-8 pretty JSON 和结尾换行，执行 flush 与 `sync_all`，再原子替换 sidecar。只有 sidecar 成功后才更新应用数据缓存；缓存失败只记录无路径、无私人素材信息的警告，不否定已经安全提交的 sidecar。这样避免两个目录之间不存在跨文件系统事务时，内存回滚却留下更新 sidecar 的矛盾状态。

sidecar 写入或替换失败时，现有命令级回滚保持不变：项目内容与撤销历史恢复到编辑前状态，UI 显示保存失败。只读目录、无空间、临时文件创建失败和替换失败都属于显式错误。应用绝不修改源 MP4，也不删除用户提供的 JSON。

## 验证

Rust 测试覆盖文件名推导（中文、空格和引号）、sidecar 与应用数据缓存同时写入、sidecar 优先于旧缓存、旧缓存自动兼容、损坏/schema 不支持/指纹不匹配时拒绝覆盖、长项目区间与播放位置往返，以及 sidecar 保存失败时项目和撤销历史回滚。文档和状态栏明确说明设置保存到同目录 JSON。最低验证为 `cargo fmt --check`、相关 Rust 测试、`pnpm check` 和 `git diff --check`。
