# 空白启动与恢复诊断设计

## 目标

SpyCut 正常启动时始终显示空白首页，不再依据应用数据目录中的最近项目缓存自动打开上一次视频。用户手动选择某个源视频后，仍按既有规则校验该视频，并优先从视频旁边的 `<完整文件名>.spycut.json` 恢复删除区间、播放位置和复核状态。由文件关联或启动参数明确传入的视频继续自动打开，因为这属于用户本次启动的显式意图。

## 方案

前端初始化只处理 `get_launch_source` 返回的显式启动文件；没有启动文件时直接停留在空白首页，不再调用 `get_session` 从磁盘恢复最近项目。后端 `get_session` 收窄为只返回当前进程内已经打开的会话，移除读取 `projects/` 最近缓存、探测旧视频、计算指纹和发布预览的隐式恢复路径。应用数据中的 `projects/*.json` 继续作为旧缓存迁移和用户随后手动选择视频时的兼容来源，不自动删除，也不再控制启动页面。

手动 `open_source` 已记录开始、媒体探测、指纹、项目匹配和完成事件；本次补齐错误事件，使探测、指纹、项目读取、保存或预览发布失败时，日志能保留失败阶段和脱敏错误。`get_session` 只记录命中当前内存会话或返回空白，不记录路径。这样既避免恢复崩溃循环，也能在用户手动重现问题时判断最后完成的阶段。

## 验证

- 前端测试确认 Tauri 正常启动不会调用 `get_session`，并显示空白首页。
- 前端测试确认显式启动文件仍调用 `open_source`。
- Rust 测试覆盖受控阶段日志事件和隐私脱敏；现有项目存储测试继续保证手动选择同一视频时可恢复 sidecar/旧缓存。
- 运行 `pnpm check`、真实 FFmpeg 波形测试、Windows x64 目标 Clippy 和 `git diff --check`，随后发布补丁版本。
