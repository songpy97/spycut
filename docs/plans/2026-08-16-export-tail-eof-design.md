# 导出尾删区间 EOF 修复设计

## 问题

项目删除区间使用容器时长作为上界，但视频流可能比容器提前结束。当前视频 PTS 只在源时间到达某个删除区间的 `end` 后扣除该区间的完整时长。若最后一个删除区间覆盖视频 EOF、却结束于更晚的容器 EOF，过滤链就不会从 EOF 中扣除已经经过的尾删时间。后续 `fps` 会依据这个未压缩的 EOF 复制最后一帧，令输出比编辑计划更长。

真实样本的最后删除区间为 `10851.337584..10875.235000`，视频 EOF 为 `10875.141667`。错误输出为 101083 个 CFR 帧，即 `6154.774395` 秒；它与计划 `6130.990375` 秒正好相差 `23.784020` 秒。

macOS 当前随包 FFmpeg 8.0.1 还存在独立的 `aselect` 回归：音频过滤器不丢弃任何帧。即使 `-shortest` 掩盖了容器时长，音频内容仍会与剪切后的视频错位。

## 方案选择

不采用放宽验收容差或只在输出末尾强制 `trim`。前者会提交错误视频；后者虽然能去掉补帧，却保留错误的过滤 EOF，也可能掩盖更早的时间轴问题。也不在视频前无条件补帧到容器时长，因为较大的流时长缺口应该由验收暴露，而不应被静帧填满。

视频改为从每个删除区间中扣除“截至当前源时间已经经过的重叠时长”：`min(max(T-start, 0), duration)`。对区间前后的保留帧，这与既有完整区间扣减完全等价；当 EOF 落入尾删区间时，它会只扣除已经过的删除部分，使 EOF 正好压缩到最后保留区间终点；当 EOF 落在保留区间时，输出仍会保持真实的提前结束并由验收报告。

音频不再依赖 `aselect`。解码音频先切成 32 样本小包，再由 `asegment` 按删除区间边界顺序分段；删除片段接入 `anullsink`，保留片段从零重排后用音频 `concat` 顺序连接，最后按样本数重建连续 PTS。`asegment` 仍读取解码器原始墙钟时间轴，保持 VFR 输入约束，并绕过 FFmpeg 8.0.1 的失效实现。相比为每个保留区间复制整条音轨，顺序分段不会让长视频的音频过滤工作量随区间数成倍增长。最初的一次性宽分段实现后来被真实 Windows 多区间项目证实会触发滤镜消费者资源错误，生产拓扑已由 `2026-08-17-bounded-audio-filter-design.md` 改为二路链式分段和合并。

## 验证

- 单元测试锁定视频 PTS 使用区间重叠而不是 `gte(end)`，并覆盖尾删区间。
- 过滤脚本测试锁定音频为 `asetnsamples -> asegment -> concat -> asetpts`，且不再出现 `aselect`。
- 真实 FFmpeg 回归使用短合成媒体验证：视频流早于容器/音频结束且 EOF 落在尾删区间时，输出时长贴合编辑计划；多个保留区间的音频内容和时长连续。
- 时长验收失败必须同时报告实际时长、计划时长、有符号差值和绝对差值，避免仅凭绝对差值反推错误方向。
