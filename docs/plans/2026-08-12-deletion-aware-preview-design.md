# 删除区间感知预览设计

## 目标与行为

普通预览需要接近最终导出的观看体验：当播放从保留内容进入删除区间时，播放器自动定位到该区间终点并继续播放。用户仍然需要能够检查被删除的原始内容，因此一次明确的手动定位（时间轴点击或拖动、区间列表定位、前后跳转、键盘定位）如果落在删除区间内部，应临时放行该删除区间，按原始时间轴正常播放。播放离开这个区间后，临时放行立即失效，后续删除区间继续自动跳过。

删除区间采用左闭右开边界：`startUs <= timeUs < endUs` 属于删除区间。手动定位到起点会放行，定位到终点不会放行。自动跳过不仅检查当前播放位置是否位于删除区间，也检查相邻播放更新之间是否跨过了区间起点，避免很短的删除区间被视频帧回调越过。

连接点复核继续使用现有 `reviewJump` 流程。复核流程显式播放删除区间前后的连接效果，因此它优先于普通预览跳过逻辑，避免同一次播放触发两套跳转。

## 结构与状态

新增播放器纯逻辑 `DeletionPlaybackGuard`，只保存上一次观察到的源时间和当前被手动放行的区间 ID。它接收规范化删除区间，返回需要跳过的第一个区间，不直接访问 DOM、Svelte 状态或播放器。`App.svelte` 在所有明确定位完成前登记手动位置；收到播放时间更新时调用 guard，并在需要跳过时让 `PlayerPane` 定位到区间终点。

自动定位期间设置单次跳转锁，防止 `requestVideoFrameCallback` 和 `timeupdate` 的重复事件发起并发 seek。定位成功后继续播放并同步 guard；定位失败则暂停播放并显示错误，避免在失败区间内不断重试或意外播放待删除内容。删除区间的持久化、规范化、复核状态和导出逻辑均不改变。

## 验证

纯逻辑测试覆盖：从保留区间进入删除区间、一次更新跨过完整短区间、手动落入区间后的临时放行、离开后恢复跳过、暂停状态不跳过，以及起止边界。前端类型检查和现有 Vitest 套件用于确认 Svelte 集成与既有时间轴行为没有回归。
