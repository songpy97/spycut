# VFR 导出时间基回归修复设计

## 问题与目标

v1.1.0 为修复 VFR 片段按帧数计时的问题，在视频 `select` 和音频 `asetnsamples/aselect` 之前增加了 `setpts=PTS-STARTPTS` 与 `asetpts=PTS-STARTPTS`。真实 Windows HEVC/AAC 样本随后从原来的时长偏差变为仅输出约 17 分 44 秒。该结果与过滤链看到的时间轴约为源墙钟时间的八分之一高度吻合，说明预归零表达式把某条非标准轨道 timebase 的整数 PTS 直接带入了后续链路。现有合成媒体使用常见视频和 48 kHz 音频时间基，因此没有覆盖这种输入。

修复必须同时满足两点：删除区间仍按解码器提供的原始墙钟 `t` 选择；选择后的输出时间戳不再依赖上游整数 PTS 的单位。自动验收、`-shortest`、删除区间补集、源文件只读和统一重编码规则保持不变。

## 方案选择

方案一是移除 `-shortest`，可以避免较短流截断另一条流，但会提交尾部缺音或缺画面的错误成片，排除。方案二是在选择前使用 `settb/asettb=AVTB` 并继续预归零；它能显式重标 timebase，但仍改变已经在 v1.0.4 真实样本上工作过的选择输入语义。方案三是恢复原始选择语义，先按解码器原始 `t` 执行 `select/aselect`，再用 `settb/asettb=AVTB` 对选中帧进行有损失保护的时间基重标，并在视频侧用秒变量 `T/STARTT` 生成压缩后的 PTS。采用方案三，改动边界最小，也能把“选择源时间”和“生成输出时间戳”分开。

## 过滤图与边界

视频先按既有 `[start,end)` 补集表达式选择。选择后 `settb=AVTB` 会在保持实际秒值的前提下把 PTS 重标为微秒时间基。第二个 `setpts` 使用 `T-STARTT+first_keep_start` 恢复项目零基准源时间；对所有已经结束的删除区间减去其持续时间，再除以明确的 `TB` 生成输出 PTS。首段就是删除区间时，`first_keep_start` 使第一帧在扣除首段删除后仍从零开始。最后由 `fps` 统一 CFR。

音频恢复 v1.0.4 的顺序：`asetnsamples` 将解码样本拆成 32 样本小包，`aselect` 继续读取未被预归零破坏的墙钟时间；选择后 `asettb=AVTB`，再用 `N/SR/TB` 按保留样本数生成连续时间戳。`-shortest` 继续作为安全约束，因为自动验收仍要求音视频时长差不超过一帧。

## 验证

过滤脚本单元测试必须禁止 `select` 或 `aselect` 前出现 `setpts/asetpts`，要求选择后存在 `settb/asettb=AVTB`，并锁定首段删除与多删除区间的秒值表达式。真实 FFmpeg VFR fixture 强制使用 `1/6000` 视频轨道 timebase 并通过 ffprobe 断言，继续覆盖低帧密度 VFR、首段删除、H.264/H.265、逐帧顺序、分数帧率和无音频；新增多删除区间 VFR 用例，防止只在单区间或标准 timebase 样本上通过。最终运行 `pnpm check`、显式忽略媒体测试和工作树/进程清理检查。
