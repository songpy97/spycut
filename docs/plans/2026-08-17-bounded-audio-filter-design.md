# 有界音频分段滤镜设计

## 问题与约束

v1.1.2 为绕过 FFmpeg 8.0.1 中失效的 `aselect`，把所有删除边界一次性交给一个 `asegment`，再把全部保留段一次性交给一个 `concat`。真实项目含 40 个删除区间，因此该图会建立 80 个 `asegment` 动态输出和一个 40 输入的 `concat`。Windows 随包 FFmpeg 在编码尚未收到首帧、输出尚未写入任何数据包时，从复杂滤镜消费者返回 `AVERROR(ENOSPC)`；界面将其误显示为磁盘空间不足。

修复仍必须在解码器原始墙钟时间轴上筛选音频，继续使用 `asegment`，不能恢复有缺陷的 `aselect`，也不能为每个保留区间复制整条长音轨。输出 PTS 仍须依据实际保留样本数连续生成。

## 方案比较

1. **二路链式分段与合并（采用）**：每个 `asegment` 只处理一个绝对时间边界，输出当前段和剩余尾部；删除段接入 `anullsink`，保留段从零重排。保留段再通过二输入 `concat` 逐个合并。任一滤镜节点的扇入、扇出恒为 2，处理量仍为一次顺序解码。
2. **固定批次分段**：每个 `asegment` 最多输出 8 段，再分批连接。图深度较小，但批次边界和标签管理更复杂，仍保留动态多输出路径。
3. **多次 FFmpeg 或中间音频文件**：每段独立导出后再合并。会重复解码或产生大量临时文件，扩大取消、清理和磁盘故障面，不采用。

## 数据流与错误处理

输入先用 `asetnsamples=n=32:p=0` 缩小边界量化误差。第 N 个 `asegment` 读取仍保留原始 PTS 的尾部流，仅按第 N 个绝对边界切成两路；前一路立即进入保留或丢弃处理，后一路继续交给下一个边界。每个保留段执行 `asettb=AVTB,asetpts=N/SR/TB`，二路 `concat` 链按时间顺序累积，末尾再以 `asetpts=N/SR/TB` 重建全局连续 PTS。没有内部边界时保持现有直通路径。

## 验证

- 单元测试锁定单个 `asegment` 只含一个时间戳和两个输出，且所有 `concat` 都是 `n=2`。
- 新增 40 个删除区间的回归，断言不会重新生成宽扇出/宽扇入图。
- 使用真实 FFmpeg 合成带音频短媒体，运行 40 区间完整导出并执行现有时长与音画差验收。
- 运行 Rust 测试、格式检查、`pnpm check` 与工作树检查；Windows 真机仍需用同一项目完成最终回归。
