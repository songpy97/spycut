# SpyCut V1 开发文档

版本：1.0  
日期：2026-08-10  
状态：产品与架构方案已确认，等待进入开发  
详细实施计划：[2026-08-10-spycut-v1.md](./plans/2026-08-10-spycut-v1.md)

## 1. 文档目的

本文档定义 SpyCut 第一版的产品范围、操作流程、系统架构、数据结构、精确导出方案、性能目标、错误处理、安全边界、测试标准和开发顺序。

第一版只解决一个问题：

> 将一段几小时的直播录屏中不适合公开的区间标记出来，确认后按原始顺序精确裁切并导出，再交给专业剪辑软件继续加工。

SpyCut 不是通用剪辑软件，也不尝试成为剪映、Premiere 或 DaVinci Resolve 的替代品。

## 2. 已确认的技术决策

| 项目 | 第一版决定 |
|---|---|
| 桌面框架 | Tauri 2 |
| 核心语言 | Rust |
| 前端 | Svelte 5 + TypeScript + Vite |
| 视频预览 | Tauri WebView 中的 HTML Video |
| 媒体分析 | ffprobe |
| 媒体导出 | FFmpeg |
| 项目存储 | 本地、版本化 JSON |
| 主要输入 | H.265/HEVC MP4 |
| 兼容输入 | H.264/AVC MP4 |
| 输出 | MP4；视频保持 H.265/H.264 编码家族；音频统一 AAC |
| 裁切精度 | 一帧以内，不再按关键帧向前后偏移几秒 |
| 导出策略 | 顺序解码完整源视频，只选择保留帧，统一硬件重编码成一个连续流 |
| 网络 | 第一版完全离线，不上传、不统计、不登录 |
| 平台 | macOS、Windows；不做 Linux |

## 3. 用户场景

典型输入：

- 直播课屏幕录制；
- 时长约 2～4 小时；
- 文件大小几 GB 到几十 GB；
- H.265 MP4 为主，H.264 MP4 需要兼容；
- 通常包含一个视频轨和一个音频轨。

典型删除内容：

- 老师说错或重复的内容；
- 等待学生、处理设备问题的空档；
- 查看学生代码的片段；
- 与学生私聊的片段；
- 其他不能公开的画面或声音。

典型输出：

- 原视频约 3 小时；
- 删除大量无关内容；
- 输出少于 1 小时；
- 再导入专业剪辑软件完成字幕、配音、封面、转场等工作。

## 4. 产品原则

### 4.1 原视频永远不变

- 打开时只读；
- 不执行“导入复制”；
- 不修改元数据；
- 不覆盖源文件；
- 导出失败、取消或软件崩溃，都不能影响源文件。

### 4.2 软件内部不存在可移动片段

SpyCut 不保存“剪辑片段”，只保存删除区间：

```text
DeleteInterval = [原视频开始时间, 原视频结束时间)
```

保留区间始终由程序计算：

```text
保留区间 = 完整源视频时间 - 所有删除区间
```

因此在数据模型中就不存在以下错误：

- 片段被误拖动；
- 片段顺序被打乱；
- 片段相互覆盖；
- 片段间产生意外空白；
- 删除后无法恢复原内容。

### 4.3 原始时间轴永远固定

所有标记都使用原视频时间。即使中间删除了两个小时，后面的标记时间也不会因为前面的删除发生变化。

例如：

```text
原视频 02:10:30 处的标记永远叫 02:10:30
```

这能让老师始终按照录课时的原始时间定位内容。

### 4.4 默认优先保护隐私

- 导出前必须进入复核页面；
- 每一个连接点都可单独试听、试看；
- 未复核区间有明显提示；
- 修改删除区间后，相应的复核状态自动失效；
- 导出完成后还会自动检查每个连接点能否正常解码。

## 6. 详细操作设计

### 6.1 空白页

软件启动后只显示一个主要按钮：

```text
打开录屏
```

正常启动保持空白，不自动打开最近项目。由文件关联或启动参数明确指定视频时可以直接进入打开流程，但仍必须重新探测并核对源文件指纹；不能因为路径相同就直接相信文件未变化。

### 6.2 打开视频

1. 用户选择 MP4。
2. Rust 将路径规范化，并只授权当前文件给 WebView。
3. ffprobe 读取媒体信息。
4. 程序验证容器和编码。
5. 程序计算轻量文件指纹。
6. 如果找到匹配项目，提示继续上次进度。
7. WebView 加载视频，不复制、不预转码。

如果路径相同但文件大小、修改时间或边缘哈希不同，必须提示“源文件已发生变化”，不能自动套用旧标记。

### 6.3 主界面

```text
├─────────────────────────────────────────────┬───────────────────────┤

│                                             │ 01  00:12:14–00:13:02 │
```

### 6.4 播放快捷键

| 操作 | 快捷键 |
|---|---|
| 播放/暂停 | `Space` |
| 后退/前进 1 秒 | `Left` / `Right` |
| 后退/前进 5 秒 | `Shift + Left/Right` |
| 后退/前进 30 秒 | `Cmd/Ctrl + Left/Right` |
| 降速 | `J` |
| 暂停 | `K` |
| 加速 | `L` |
| 删除区间开始 | `I` 或 `[` |
| 删除区间结束 | `O` 或 `]` |
| 取消尚未完成的起点 | `Esc` |
| 删除当前标记 | `Delete` |
| 撤销 | `Cmd/Ctrl + Z` |
| 重做 | `Cmd/Ctrl + Shift + Z` |

倍速范围：0.5×、0.75×、1×、1.25×、1.5×、2×。

### 6.5 标记删除区间

1. 单击时间轴或按住鼠标连续拖动播放头，到达不应公开内容的开头。
2. 点击“设删除起点”，也可按 `I`。
3. 继续播放或拖动播放头；工具栏持续显示待完成状态和起点时间。
4. 到结束位置点击“完成删除区间”，也可按 `O`。
5. 时间轴立即出现红色区域。
6. Rust 规范化并自动保存项目。

尚未结束的删除区间使用琥珀色斜纹显示。工具栏提供“取消”按钮，也可按 `Esc` 取消。保存失败时必须保留待完成起点，显示错误并允许重试。

规则：

- 结束位置必须晚于开始位置；
- 删除区间不能超出源视频；
- 重叠区间自动合并；
- 完全相邻的区间自动合并；
- 区间主体不能拖动；
- 只有左右边界能调整；
- 删除标记只是恢复该段内容，不影响原文件。

### 6.6 单一编辑时间轴

主界面只能存在一条带刻度、播放头和编辑能力的时间轴。其内部视口独立于播放头：定位时只更新播放头；只有播放头离开可视范围，或播放期间进入右侧跟随阈值时，视口才自动平移。这避免了拖动播放头时轨道反向滑动。

时间轴由四层组成：

1. 工具栏：撤销、重做、删除起点、删除终点、取消、时间码、帧吸附状态和缩放控制。
2. 自适应标尺：依据当前视口跨度和像素宽度选择刻度密度；高倍率下可用于逐帧定位。
3. 主轨：显示锁定的源时间轴、删除区间、待完成区间、悬停位置和唯一播放头。
4. 全片细导航条：只显示删除分布和当前视口窗口，不显示第二套刻度或播放头，因此不构成第二条编辑时间轴。

指针操作：

- 在标尺、轨道空白、删除区间主体或播放头上按住左键并左右拖动，进入连续 Scrub；按下时暂停，拖动中更新乐观播放头和预览帧，松手执行一次精确 Seek 并保存最终播放位置。
- Pointer 手势必须使用 Pointer Capture；`pointercancel`、丢失捕获或 `Esc` 应取消手势，Scrub 还原拖动前位置，区间调整不提交。
- 删除区间主体不可移动。单击或拖动主体只会选中区间并移动播放头。
- 选中区间后显示左右边界手柄。拖动中只更新临时边界并按源帧吸附；松手只发送一次 `resize_delete_interval`。后端返回的规范化区间仍是唯一真相。
- 指针靠近主轨左右边缘时，Scrub 和边界调整会自动平移视口，允许跨越当前窗口持续拖动。

缩放与导航：

- `Alt/Option + 滚轮` 或 `Ctrl + 滚轮` 以鼠标所指时间为锚连续缩放。
- 触控板横向滑动或 `Shift + 滚轮` 水平平移视口。
- 工具栏提供对数缩放滑杆、缩小、放大和“适配全片”，不要求用户记住手势。
- 拖动细导航条中的窗口可跨小时平移；单击窗口外会把视口中心移到目标位置。
- 缩放最小跨度不得小于 20 帧，最大跨度不得超过源视频时长；所有坐标和结果都要夹在合法范围内。

拖动预览采用两阶段 Seek：`PlayerPane` 以 `requestAnimationFrame` 合并高频预览请求，`HtmlVideoAdapter.previewSeekTo` 不等待 `seeked`；松手后才调用可等待、带超时的精确 `seekTo`。新媒体加载、精确 Seek 或组件销毁时必须取消尚未执行的预览请求，防止过期位置回跳。

第一版不生成全片波形或缩略图，避免几小时视频打开后进行大规模扫描和缓存。触控板 pinch 仅在目标 WebView 事件行为可可靠验证后接入，不作为当前验收条件。

### 6.7 复核页面

点击“检查并导出”后，先进入复核页，不立即执行 FFmpeg。

页面显示：

- 原始时长；
- 删除总时长；
- 预计成片时长；
- 连接点数量；
- 已复核和未复核数量；
- 预计输出大小；
- 输出编码器；
- 剩余磁盘空间；
- 兼容性警告。

每个删除区间的复核方式：

1. 从删除起点前 3 秒开始播放；
2. 到删除起点时模拟跳到删除终点；
3. 继续播放 3 秒；
4. 显示切口前最后一个保留画面和切口后第一个保留画面；
5. 用户确认该连接点，或返回编辑。

WebView 虚拟跳转可能有短暂停顿，它只用于确认内容语义，不代表最终编码文件的播放流畅度。

### 6.8 导出页面

1. 用户选择输出 MP4。
2. 禁止输出路径与源文件相同。
3. 如果目标已经存在，先询问，但仍不能直接在原文件上写。
4. 创建唯一的 `.partial.mp4`。
5. 锁定当前标记快照。
6. 启动 FFmpeg。
7. 显示扫描进度、编码进度、耗时和取消按钮。
8. FFmpeg 成功后进行验证。
9. 验证通过才将 partial 文件提升为最终输出。

导出过程中不允许修改删除区间。取消或失败后回到复核状态。

## 7. 系统架构

```text
┌──────────────────────────────────────────────────────────────┐
│ Tauri WebView                                               │
│ Svelte + TypeScript                                         │
│ - 页面与组件             - 视频控件                         │
│ - 单一编辑时间轴         - 复核和导出界面                   │
└───────────────────────┬──────────────────────────────────────┘
                        │ 类型化 Tauri command / event
┌───────────────────────▼──────────────────────────────────────┐
│ Rust Core                                                   │
│                                                              │
│  领域层               应用层                基础设施层       │
│  - 时间与区间          - 当前项目会话        - 项目 JSON      │
│  - 规范化与补集        - 撤销/重做           - 文件指纹       │
│  - 媒体信息            - 复核状态            - ffprobe        │
│  - 导出计划            - 导出任务            - FFmpeg         │
│                                              - 验证与日志     │
└───────────────────────┬──────────────────────────────────────┘
                        │ 受监督子进程
              ┌─────────▼──────────┐
              │ ffprobe / ffmpeg   │
              └─────────┬──────────┘
                        │
           源 MP4（只读）→ partial MP4 → 验证 → 最终 MP4
```

整体是单机模块化单体应用，不需要：

- 后端服务器；
- 外部或远程 HTTP API（视频预览使用进程内受限回环 HTTP Range 服务）；
- 数据库；
- 消息队列；
- 后台常驻服务。

建议的前端调用：

```text
open_source()

undo()
```

建议的 Rust 事件：

```text
session://changed

```

所有导出事件都必须带 `job_id`。前端忽略旧任务的迟到事件。

## 10. 数据模型

### 10.1 时间

Rust 统一使用 64 位整数微秒：

```rust
type Micros = i64;
```

不使用浮点秒保存项目，避免多次保存、计算后产生边界漂移。

### 10.2 删除区间

```rust
struct DeleteInterval {
    id: u64,
    start_us: i64,
    end_us: i64,
}
```

区间为半开区间 `[start_us, end_us)`。

### 10.3 项目

```json

  "projectId": "...",
  "source": {
    "canonicalPath": "/path/to/课程01.mp4",
    "sizeBytes": 1234567890,
    "modifiedUnixMs": 1780000000000,
    "edgeHashBlake3": "..."
  },
  "media": {
    "durationUs": 11545000000,
    "container": "mp4",
    "videoCodec": "hevc",
    "width": 3840,
    "height": 2160,
    "frameRate": {"num": 30, "den": 1},
    "variableFrameRate": false,

    "audioStreamCount": 1,
```

`ProjectV1` 原子保存在源视频同目录的 `<视频完整文件名>.spycut.json`，例如 `课程 01.mp4.spycut.json`。源视频本身始终只读；视频目录必须允许创建和替换该项目文件。应用数据目录保留一份兼容缓存，只在用户手动或显式打开视频而同目录 sidecar 不存在时按指纹迁移；它不控制正常启动页面，重新导入时仍以同目录 JSON 为准。

### 10.4 文件指纹

为了避免读取几十 GB 文件计算完整哈希，第一版使用：

```text
文件大小
+ 修改时间
+ 文件头 1 MiB
+ 文件尾 1 MiB
→ BLAKE3
```

导出前重新核对。如果不一致，必须停止。

## 11. 视频预览方案

第一版使用 HTML `<video>`，让 WKWebView 或 WebView2 直接完成解码和显示。

禁止采用以下数据流：

```text
FFmpeg 解码 → Rust 原始帧 → Tauri IPC → JavaScript → Canvas
```

4K YUV420 单帧约 12 MiB，30 fps 约 360 MiB/s；转成 RGBA 后接近 1 GiB/s。跨 IPC 和 WebView 传输会产生大量内存复制，与低占用目标冲突。

### 11.1 H.265 能力检测

1. 先使用 `canPlayType` 提示能力。
2. 真实加载所选视频，并等待 `loadedmetadata`/`canplay`。
3. 设置有限等待时间。
4. 如果 WebView 失败，再让 FFmpeg 解码短片段。
5. 区分：
   - WebView 缺少 H.265 支持；
   - FFmpeg 也无法解码；
   - 文件不可读；
   - MP4 元数据损坏。

Windows 上 H.265 需要可用的 HEVC 解码路径，通常涉及 HEVC Video Extension。软件要提供明确说明，而不是笼统显示“文件损坏”。

### 11.2 未来替换能力

前端通过 `MediaPlayerAdapter` 使用播放器。第一版是 `HtmlVideoAdapter`。如果未来需要完全内置的 H.265 播放器，可以增加 libmpv 原生适配器，而不修改区间和导出核心。

## 12. 精确导出方案

### 12.1 为什么第一版不只重编码关键帧附近

H.265 边界智能渲染需要确保原视频和新编码 GOP 的以下参数兼容：

- VPS/SPS/PPS；
- Profile、Level；
- 像素格式和位深；
- 色彩空间和 HDR 元数据；
- B 帧顺序；
- DTS、PTS；
- MP4 sample description。

不同硬件编码器可能产生不同参数。拼接文件可能在播放器里能播，但进入专业剪辑软件后花屏或报错。

因此第一版不冒这个风险。

### 12.2 第一版算法

1. 顺序读取并解码完整源视频。
2. 将源时间规范到从 0 开始。
3. 根据保留区间选择视频帧。
4. 丢弃删除区间中的帧。
5. 将保留帧重新编号为连续 CFR 时间轴。
6. 对音频执行相同的区间选择并连续编号。
7. 使用一个硬件视频编码会话输出。
8. 音频重编码为 AAC。
9. 复用一个 MP4 muxer 生成结果。

这意味着：

- 完整三小时源视频需要被解码一遍；
- 只有最终保留的不到一小时需要视频编码；
- 不生成几十个临时片段；
- 不需要双倍成片大小的临时空间；
- 输出只有一套统一的 H.264/H.265 参数；
- 裁切误差不再是几秒，而是最多一帧。

### 12.3 过滤表达式

假设需要保留：

```text
[0, 125.400)
[140.200, 300.000)
```

30 fps 视频的概念过滤图：

```text
[0:v:0]
select='gte(t,0)*lt(t,125.400)+gte(t,140.200)*lt(t,300.000)',
settb=AVTB,
setpts='(T-STARTT+0-min(max(T-STARTT+0-125.400,0),14.800))/TB',
fps=30:start_time=0
[vout]
```

音频：

```text
[0:a:0]
asetnsamples=n=32:p=0[arem0];
[arem0]asegment=timestamps=125.400[apart0][arem1];
[arem1]asegment=timestamps=140.200[apart1][arem2];
[apart0]asettb=AVTB,asetpts=N/SR/TB[akeep0];
[apart1]anullsink;
[arem2]asettb=AVTB,asetpts=N/SR/TB[akeep1];
[akeep0][akeep1]concat=n=2:v=0:a=1[ajoin1];
[ajoin1]asettb=AVTB,asetpts=N/SR/TB
[aout]
```

音视频先在解码器提供的原始 `t` 时间轴上筛选，避免筛选前的裸 `PTS-STARTPTS` 改变非标准轨道 timebase 的语义。视频筛选后由 `settb=AVTB` 在保持实际秒值的前提下重标 timebase，再以 `T/STARTT` 扣除当前源时间与删除区间的累计重叠时长，最后由 `fps` 过滤器统一为 CFR。累计重叠表达式也会处理 EOF 落入尾删区间的情况，避免 `fps` 按未压缩 EOF 补回最后一帧。音频由一系列二路 `asegment` 在原始时间轴上按绝对删除边界顺序切分，每个节点只输出当前段与剩余尾部；删除段接入 `anullsink`，保留段从零重排后由二输入 `concat` 链串接，最后按保留样本数生成连续时间戳。固定每个节点的扇入和扇出可以避免大量区间在 Windows FFmpeg 中触发滤镜消费者资源错误，同时继续绕过 FFmpeg 8.0.1 中失效的 `aselect`，也不会让长音轨的解码处理量随区间数成倍增加。

实际代码从整数微秒生成过滤脚本文件，不将表达式和用户路径拼入 shell 字符串。

### 12.4 编码器选择

| 平台 | H.265 优先顺序 | H.264 优先顺序 |
|---|---|---|
| macOS | VideoToolbox | VideoToolbox |
| Windows NVIDIA | NVENC | NVENC |
| Windows Intel | QSV | QSV |
| Windows AMD | AMF | AMF |
| 最后回退 | 经许可审查的软件编码器 | 经许可审查的软件编码器 |

不能只检查 FFmpeg 是否列出编码器。每台机器需要执行一个很短的真实编码测试，再决定该编码器可用。

第一版界面只显示一个“高质量”产品预设，不暴露几十个编码参数。各硬件编码器使用独立参数配置，并用真实的代码界面录屏校准文字锐度、色彩、速度和文件大小。

### 12.5 帧率

精确导出将输出规范为 CFR，帧率来自可信的源视频名义帧率，例如：

- 30；
- 60；
- 30000/1001；
- 60000/1001。

如果检测到明显 VFR，复核页必须显示将要使用的输出帧率。验证阶段检查最终时长和音画漂移。

### 12.6 进度

只看 FFmpeg 输出时长会出现问题：当程序正在扫描一大段将被删除的源内容时，没有输出帧，进度条看起来会停住。

所以需要同时记录：

- 已处理的源视频时间；
- 已产生的成片时间；
- 编码速度；
- 当前阶段。

总体进度以“已处理源时间 / 源总时长”为准。

FFmpeg 连续 60 秒没有任何输入进度时显示“可能卡住”，但不自动杀死进程。用户可以查看日志并取消。

### 12.7 子进程规则

- Rust 直接传参数数组；
- 不使用 `sh -c`、`cmd /C` 或 PowerShell 字符串；
- 始终添加 `-nostdin`；
- ffprobe、能力检测和输出验证都有明确超时；
- 正式导出允许长时间运行，但必须有进度和取消；
- 取消后先终止并回收进程，再删除自己创建的 partial 文件；
- 应用退出前不能留下 ffmpeg/ffprobe 孤儿进程。

## 13. 输出验证

FFmpeg 返回 0 还不代表成片可交付。partial 文件需要通过：

- ffprobe 能读取；
- 存在一个预期的视频轨；
- 视频编码家族正确；
- 音轨存在性正确；
- 时长与保留区间总时长接近；
- 起始时间接近 0；
- 时间戳可用；
- 开头、结尾可以解码；
- 每一个连接点附近可以解码；
- 文件大小不是异常的 0 或极小值。

验证通过后才将 partial 文件变为用户选择的最终文件。

## 14. 项目保存和恢复

项目真相源与启动缓存：

```text
源视频目录/
├── 课程 01.mp4
└── 课程 01.mp4.spycut.json     # 项目真相源

系统应用数据目录/
├── projects/<project-id>.json # 旧项目兼容迁移缓存，不触发自动打开
└── jobs/<job-id>/             # 导出中断恢复记录
```

每一次有效编辑：

1. 在工作流锁内修改 Rust 内存模型；
2. 将 `ProjectV1` 序列化为 UTF-8 JSON；
3. 在源视频目录写入同盘临时文件；
4. flush 并 `sync_all`；
5. 使用平台安全的替换方式原子提交 sidecar；
6. sidecar 成功后尽力刷新应用数据启动缓存。

选择视频时先探测并计算首尾指纹。sidecar 存在时必须优先读取并校验 schema、大小和首尾哈希；不存在时才按指纹读取旧版应用数据缓存，并在本次打开保存时自动生成 sidecar。损坏、版本过新或与当前视频不匹配的 sidecar 必须停止读取并原样保留，不能静默回退到缓存或覆盖为空项目。

如果 sidecar 保存失败，内存项目与撤销历史必须回滚，界面持续显示警告，不能假装已经保存。应用数据缓存刷新失败不撤销已经原子提交的 sidecar；下次手动导入仍能从视频旁恢复完整设置。

撤销历史只保存在当前会话，最多 100 步。重启后恢复最终标记状态，但不恢复撤销栈。

## 17. 主要失败场景

| 情况 | 处理 |
|---|---|
| 源文件丢失 | 要求重新定位并核对指纹 |
| 源文件发生变化 | 停止恢复和导出，要求明确处理 |
| WebView 不能播放 H.265 | 提示 Windows HEVC 解码环境；再用 FFmpeg 判断文件是否正常 |
| ffmpeg/ffprobe 缺失 | 显示工具查找路径和环境诊断 |
| 硬件编码器不可用 | 尝试下一个已验证候选，并告知回退 |
| 磁盘空间不足 | 导出前阻止；导出中失败时保留最终文件不变 |
| FFmpeg 无进度 | 60 秒后警告并允许取消 |
| 用户取消 | 回收子进程，删除本任务 partial，返回复核 |
| 软件在编辑中崩溃 | 重启后读取最后一个原子保存的项目 |
| 软件在导出中崩溃 | 下次启动检测遗留任务，允许显示或清理 partial |
| 输出验证失败 | 不提升为最终文件，保留报告 |
| 路径含中文、空格或引号 | 参数数组调用，专项自动化测试 |

## 23. 架构决策摘要

### ADR-001：Tauri 2 + Rust + Svelte

选择原因：跨平台、界面开发快、Rust 适合管理状态和长任务。代价是 Windows H.265 依赖 WebView 解码环境。

### ADR-002：只保存删除区间

选择原因：从根本上消灭片段误移动和顺序混乱。代价是软件不能扩展为通用剪辑器，除非重新设计领域模型。

### ADR-003：第一版连续精确重编码

选择原因：保证一帧级切点和稳定 MP4。代价是导出比关键帧复制慢，并发生一次高质量有损编码。

### ADR-004：第一版使用 HTML Video

选择原因：避免原始帧跨 IPC 和原生播放器集成成本。代价是 Windows H.265 需要能力检测和明确提示。

### ADR-005：版本化 JSON

选择原因：一个项目数据量很小，不需要数据库；与视频同目录的版本化 sidecar 让设置可见、可携带，并能在重新导入时确定恢复。应用数据副本只承担旧版本兼容迁移，不触发启动自动打开。代价是视频目录必须可写，且只保存最终状态，重启后不保留撤销历史。

### ADR-006：FFmpeg/ffprobe sidecar

选择原因：隔离崩溃、方便进度和取消、避免在 Rust 中直接绑定复杂 FFmpeg C API。代价是需要处理多平台二进制和许可证。

## 24. 完成定义

不能因为界面完成或短视频成功导出，就宣布第一版完成。

完成必须同时有：

- macOS 和 Windows 真实 H.265/H.264 证据；
- 长视频和 4K 证据；
- 一帧级切点验证；
- 音画同步验证；
- 源文件未变化证明；
- 取消、崩溃、磁盘不足、验证失败测试；
- 无孤儿进程证明；
- 实际专业剪辑软件导入验证；
- 发布 FFmpeg 许可记录。
